# Архитектура MVC приложения calc-tdd

MVC (Model — View — Controller) делит приложение на три части с разной
ответственностью, чтобы логику можно было менять и тестировать
независимо от интерфейса.

```
          HTTP-запрос / аргументы CLI
                     │
                     ▼
        ┌────────────────────────────┐
        │ Controller                 │  controller.py, cli.py
        │ принимает ввод, проверяет, │
        │ вызывает модель            │
        └─────────────┬──────────────┘
                      │ calculate(op, a, b)
                      ▼
        ┌────────────────────────────┐
        │ Model                      │  model.py
        │ Calculator, Record,        │
        │ CalculatorError, история   │
        └─────────────┬──────────────┘
                      │ Record
                      ▼
        ┌────────────────────────────┐
        │ View                       │  views.py
        │ JSON-схемы, текстовый      │
        │ формат «2 + 3 = 5»         │
        └─────────────┬──────────────┘
                      ▼
               JSON / строка в консоли
```

## Model — `src/calc_tdd/model.py`

- `Calculator` — выполняет операции, хранит историю с ограничением длины.
- `Record` — неизменяемая запись об одном вычислении.
- `CalculatorError` — ошибки предметной области (деление на ноль, корень из
  отрицательного числа, неизвестная операция).

Модель не импортирует FastAPI, argparse или pydantic. Поэтому её тесты
(`tests/test_calculator.py`) самые быстрые и не зависят от интерфейса.

## View — `src/calc_tdd/views.py`

- `CalculationRequest` — какие данные ждём от клиента (pydantic проверяет
  типы и допустимые операции, иначе 422).
- `CalculationResponse` — как запись выглядит в JSON.
- `as_text()` — как та же запись выглядит в консоли.

Одна модель — два представления: JSON для API и текст для CLI.

## Controller — `src/calc_tdd/controller.py` и `src/calc_tdd/cli.py`

- REST-контроллер: маршруты `/calculate`, `/history`, `/operations`,
  `/health`. Переводит `CalculatorError` в HTTP 400.
- CLI-контроллер: разбирает аргументы `argparse`, переводит ошибку в код
  возврата 1.

Контроллеры тонкие: в них нет вычислений, только связь ввода, модели и
представления.

## Поток запроса `POST /calculate`

1. Клиент отправляет `{"operation": "divide", "a": 10, "b": 4}`.
2. FastAPI валидирует тело по `CalculationRequest` (View).
3. Контроллер вызывает `Calculator.calculate("divide", 10, 4)` (Model).
4. Модель считает `2.5` и сохраняет `Record` в историю.
5. Контроллер строит `CalculationResponse.from_record(...)` (View).
6. Клиент получает `{"result": 2.5, "expression": "10 / 4 = 2.5", ...}`.

## Почему так

- Замена интерфейса (например, добавить GUI на Tkinter) не требует
  менять модель — нужен только новый контроллер и view.
- `create_app(calculator)` получает модель извне, поэтому в тестах у
  каждого приложения своё состояние.
- Каждый слой тестируется отдельно: `test_calculator.py` — модель,
  `test_api.py` — контроллер + view через HTTP, `test_cli.py` — CLI.
